Workshop: the Linux Command Line

You can do pretty much everything you can do in the GUI on the command line, although you might have to take a different approach. However, command line interfaces are most commonly used for system administration. Many systems, e.g., servers, don’t run a graphical user interface to leave more resources for the applications the server is hosting.

learn to navigate a Linux machine entirely from the command line, manage files, users, processes and networking, and explore aspects of system security.

Command line, shell, terminal, command prompt, tty, terminal. These terms are used interchangeably.

The Cyber‑Pi Cluster

The cluster consists of 10 Raspberry Pi 4 boards running BusyBox Linux (minimalist Linux) and OpenWrt (router firmware). Each Pi creates its own Wi‑Fi access point called something like OpenWrt‑ABC123.

Connecting to the Wi-Fi

The password is a string made from the words bsu, cyber, lab in lowercase and no spaces.

Example: bsulab or labcyberbsu.

Your first challenge is to guess the password.

Once connected, find out your IP address. This is usually shown in your system settings.

Logging in via SSH

Each Pi runs an SSH server with no password for root.

Log in using a command like

ssh root@host

where host is the IP address of the PI. Note that this address is different from the address it gave your machine, but is likely to start with the same numbers.

Side challenge Find out about IP addresses (CIDR). What class of IP address does your Pi’s network use?

You’ll be dropped into a shell as the root user. root is the “ssuperuser” or administrator. Linux has diffirent levels of privilage, for example, regular users cannot modify or delete files in certain folders, or perform certain operations. However, root can do anything, so be careful.

Don’t worry these Pi’s reset at 6pm every day, so it’s okay if you brick the system. If you do brick it, though, please make a note of how you did it, for future reference.

Running commands

If you’re new to the command line, it may seem a bit daunting. It does away with the familiar windows, icons, menus and pointer from the GUI and presents you with a blank prompt, cursor blinking threateningly, expecting you to know what to type, rather than recognise an icon to click on. It’s incredibly powerful and useful once you get the hang of it.

Commands are made up of letters, numbers and dashes. They can have options and switches. COmmands and their arguments are separated by a space. For instance:

# ls

lists all files in your current directory.

ls -l

lists all files with some additional information including its permissionns, owner, size and modified date. The -l is a flag or switch.

ls /etc

lists all files in the directory /etc — /etc is given as an argument to ls.

Some commands, like ls, produce output. Others don’t. For example

cd path/to/folder

changes your working directory to path/to/folder. Your working directory is the folder in which commands are run. When first logging in, you are in your home directory, /root, in this case. To return to your home directory, type

cd

If cd succeeds, it gives no output, but it does move you to the new directory. If the command fails, it prints out an error.

These might seem a bit esoteric at first — they are purposefully short to be easier to type.

Make yourself a cheatsheet: as you pick up more commands, make a note of the command and what it does.

Processes & Signals

  1. Run a background process

    sleep 60 &

  2. Find its PID

    ps aux | grep sleep

  3. Send it SIGTERM

    kill <PID>

  4. Re‑run it, but this time send SIGHUP

    sleep 60 &
kill -HUP <PID>

Multiple users

Creating a new user

adduser alice # prompts for password

adduser automatically creates a home directory /home/alice.

Logging in as the new user

ssh alice@hostname

You’ll be prompted for the password you set.

Sending a message to the other user

write alice

(You’ll get a prompt to type your message. Press Ctrl‑D to finish.)

Exercise

  1. Create a second user bob.
  2. Log in as bob from a separate terminal window (you can use a local SSH client).
  3. Use write to send bob a hello message from alice.

Networking – Your MAC & IP

ip link show # shows MAC addresses
ip addr show # shows IP addresses

Harden your system

  • If anyone can SSH to root@<IP>, you’re insecure.
  • Add a password for the root account:
passwd root

Now, root can no longer log in without a password.

Securing a machine with remote access

  1. Generate an SSH key pair on your local machine

    ssh-keygen -t ed25519

    (You can accept the default file location and set no passphrase for this exercise.)

  2. Copy the public key to the Pi

    ssh-copy-id root@hostname

  3. Log in without a password

    ssh root@192.168.1.23

SSH Configuration

Edit /etc/ssh/sshd_config (you may need sudo):

sudo nano /etc/ssh/sshd_config
Port 12345
PermitRootLogin no
PasswordAuthentication no
AllowUsers alice bob

Restart SSH for the changes to take effect

sudo systemctl restart sshd

Advanced (but super useful): Terminal Multiplexers

Why use them?

  • Keep sessions alive after you log out.
  • Share a terminal with another user.
  • Copy/paste inside the session without using the host OS clipboard.

Installing screen

sudo apt update
sudo apt install screen

Basic usage

  1. Start a new session

    screen -S mysession

  2. Detach (leave it running)

    Ctrl‑A then D

  3. Re‑attach

    screen -r mysession

  4. List sessions

    screen -ls

  5. Share a session with another user

    • Make sure the session is running as a shared group (e.g., both users belong to screen group).
    • The other user can screen -x mysession.

  6. Copy/paste inside screen

    • Press Ctrl‑A then Esc to enter copy mode.
    • Move the cursor to the start of the text, press Space, move to the end, press Space again.
    • Exit copy mode, press Ctrl‑A then ] to paste.

Exercises

  1. Create a screen session called demo.
  2. Run top inside the session.
  3. Detach and re‑attach to the session from another terminal.
  4. Share the session with your friend (use screen -x demo).
